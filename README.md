# Tron-Legacy-MPF

A Mission Pinball Framework (MPF) recreation of **Stern Tron Legacy Limited Edition, code v1.74**,
built from the reverse-engineered rules, media and effects in
[Ashram56/Tron-Legacy-LE-ROM-Decryption](https://github.com/Ashram56/Tron-Legacy-LE-ROM-Decryption).

## Layout

| Path | What it is |
|---|---|
| `assets/` | Git submodule: [Tron-Legacy-LE-ROM-Decryption](https://github.com/Ashram56/Tron-Legacy-LE-ROM-Decryption), the rules specs, MPF config and media read from the ROM. Never copy files out of it; reference them, so a sync never leaves stale copies. |
| `game/` | The MPF machine folder and the Godot (GMC) project in one: `config/`, `modes/`, `slides/`, `project.godot`, `gmc.cfg`. Kept apart from `assets/` so Godot does not import the asset repo's 12,000 files. |
| `scripts/` | Workspace setup (`setup.py`, `toolchain.py`), the launcher (`run.py`), the render check and the asset sync. |
| `docs/` | `hardware.md`: the two hardware configs (virtual + MPF Monitor, and the real machine on a Multimorphic P-ROC). |

## What is in git, what is not

The repository holds only platform-neutral files: the MPF code and config (`game/`), the Godot project
(`game/project.godot`, slides, scripts), the tools (`scripts/`), the tests and the docs. Everything that
depends on the OS or CPU is fetched or generated by `scripts/setup.py`, is git-ignored and lives in:

| Path | What | Per OS |
|---|---|---|
| `.venv/` | Python venv: MPF 0.80.1, pillow, pytest (+ MPF Monitor 1.0.0 with `--monitor`) | `Scripts\python.exe` on Windows, `bin/python` elsewhere |
| `tools/godot/` | Godot 4.5.2 stable, the official build | Windows `Godot_v4.5.2-stable_win64.exe`, macOS `Godot.app`, Linux `Godot_v4.5.2-stable_linux.x86_64` (arm64 builds on ARM) |
| `game/addons/mpf-gmc/` | GMC 1.0.0, the Godot media controller add-on | same on every OS |
| `game/config/rom/`, `game/sounds/`, `game/media/`, `game/slides/deffs/`, `game/fonts/`, `game/tron/media_data.json` | Generated from `assets/` by `scripts/gen_config.py` and `scripts/gen_media.py` | same on every OS |
| `game/.godot/` | Godot's import cache | rebuilt by the import |

Versions, download URLs and every per-OS path are in one file, `scripts/toolchain.py`. Set `GODOT` to use a
Godot 4.5.x you installed yourself. `python scripts/toolchain.py` prints what it found.

## Getting started

You need Git and Python 3.10 to 3.14 (3.11 is what CI uses). Clone with the asset submodule:

```sh
git clone --recurse-submodules https://github.com/Ashram56/tron-legacy-mpf.git
cd tron-legacy-mpf
```

### Windows

```bat
py -3.11 scripts\setup.py --monitor
.venv\Scripts\python scripts\run.py --monitor
.venv\Scripts\python -m pytest -q tests
```

`scripts\setup.bat` (cmd) and `.\scripts\setup.ps1` (PowerShell) run the same script. Godot goes to
`tools\godot\Godot_v4.5.2-stable_win64.exe`. Windows may ask to let Godot and Python through the firewall:
they only talk on localhost (ports 5050 and 5051), so "private networks" is enough.

### macOS (Intel or Apple silicon)

```sh
python3 scripts/setup.py --monitor
.venv/bin/python scripts/run.py --monitor
.venv/bin/python -m pytest -q tests
```

Godot goes to `tools/godot/Godot.app` (universal build, signed by the Godot project).

### Linux (x86_64 or arm64)

```sh
python3 scripts/setup.py --monitor        # scripts/setup_workspace.sh still works and runs the same
.venv/bin/python scripts/run.py --monitor
.venv/bin/python -m pytest -q tests
```

`tools/godot/godot` is a short link to the Godot binary. Without a display, `run.py` and the render check
start Godot under Xvfb (`apt install xvfb`).

`setup.py` is safe to re-run; each step is skipped when it is in place. Options: `--monitor` (MPF Monitor),
`--skip-godot` (MPF and tests only), `--upgrade` (re-run pip), `--dry-run` (print the plan), and
`--os windows|macos|linux --arch x86_64|arm64` (print the plan for another host).

## Running

`scripts/run.py` starts Godot first (GMC is the BCP server on port 5050), waits for it, starts MPF with the
hardware overlay, optionally MPF Monitor, and stops everything when MPF ends (Ctrl+C, or Esc in MPF's text
UI). Godot's log is `game/logs/godot.log`.

| Command | Hardware |
|---|---|
| `python scripts/run.py` | `hw_virtual`: smart_virtual, the trough starts full, ejects move balls, trough switches shift. |
| `python scripts/run.py --monitor` | The same plus MPF Monitor (`mpf monitor`, layout in `game/monitor/`): click switches, see lamps and coils. |
| `python scripts/run.py --scenario NAME` | Plays `assets/rules/traces/NAME.txt` in real time on smart_virtual. |
| `python scripts/run.py --hw proc` | The real machine: Multimorphic P-ROC on the Stern SAM IO board; Godot gets `-- --proc-dmd` for the DMD. |

(Use the venv's Python, as in Getting started, or any Python 3: `run.py` only needs the standard library
and finds the venv itself.) By hand, the same thing is `godot --path game`, then in `game/`:
`mpf game . -c config,hw_virtual` (or `config,hw_proc`). [docs/hardware.md](docs/hardware.md) has the details.

**P-ROC:** MPF's wheel ships the pypinproc binary for Windows (`pinproc.cp3xx-win_amd64.pyd`) and macOS
(`pinproc.so`), so on those `--hw proc` works once libusb/FTDI drivers are installed. On Linux, build and
install libpinproc and pypinproc (github.com/preble) into `.venv` first; MPF has no Linux binary.

## Tests and checks

```sh
.venv/bin/python -m pytest -q tests                   # all OSes (Windows: .venv\Scripts\python)
python scripts/render_check.py [seconds] [scenario]   # boots Godot + MPF, captures the DMD, fails if blank
.venv/bin/python scripts/scenario_report.py           # rule traces against the ROM references
```

The render check writes `captures/dmd_latest.png` and an 8x preview. Godot's `--headless` mode uses a dummy
renderer that draws nothing, so the check opens a real window with the OpenGL renderer: under Xvfb (Mesa
llvmpipe) on Linux without a display, a normal window elsewhere. `game/tools/dmd_capture.gd` does the capture;
it is inert unless Godot is started with `-- --capture-dir=...`. `scripts/render_check.sh` is a wrapper.

CI (`.github/workflows/test.yml`) runs the setup and the tests on Ubuntu, Windows and macOS, and the render
check on Ubuntu.

## Keeping assets in sync

The asset repo is still being completed. `scripts/sync_assets.sh` moves the submodule to its
latest commit and writes `captures/asset_sync.md`: commits, changed files by area, any
`UPDATE_*`/`REMOVED_*` package notes, and files deleted or renamed upstream. A scheduled routine
runs it and opens a pull request whenever the assets move.
